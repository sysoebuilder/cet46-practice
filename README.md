# 给我过 · 四六级真题

Vue 3 + Vite + Vue Router + Motion for Vue，使用 HBuilderX **5+ App** 运行和打包，面向 Android 手机、平板。薄荷绿、编辑式排版、物理弹簧交互。已移除 uni-app 编译器、JS service 和原生页面壳。

Android 安装包见 [GitHub Releases](https://github.com/sysoebuilder/cet46-practice/releases)。`v0.1.0` 完整离线包约 834 MiB，包含 119 套试卷及 74 份音频；安装后练习不依赖电脑或网页服务。

## 当前功能

- 选择级别、年份、试卷、题型后直接做题。
- 选词填空直接点击原文空位弹出词库，选择后在原文显示字母和单词，可再次点击修改；不再显示独立答题区。
- 长篇阅读、仔细阅读以原文为主，点击悬浮“答题”查看全部题目，点击题目向下展开选项。已答题直接显示“已选字母”和选项内容；填空词库同样使用顶部下拉窗口。
- 写作、翻译保留输入区域。
- 听力按原卷新闻、对话和篇章分组，同组题目在一页滚动阅读；上一题、下一题按组切换，播放不中断。
- 每次选择、输入、切换题目时同步保存到本机；重开恢复答案和题目位置。
- 首页继续上次、答题卡跳转、三档阅读字号。
- 当前题型结束后点击“下一题”进入同套下一可用题型，恢复该题型已有进度；缺失题型自动跳过，最后一个题型显示练习保存结果。
- 长篇阅读、仔细阅读页面底部的“上一题／下一题”直接切换上一／下一可用题型，保留进度，不自动弹出小题。小题通过悬浮“答题”手动选择，窗口顶部只保留关闭按钮。
- 其他题型的“上一题”返回上一小题或听力组；当前题型第一题可回到上一可用题型末题，并保留作答。
- 每个大题型有“核对答案”按钮，一次核对当前题型全部题目。正确为绿色 ✓，错误和未答为红色 ×；保留用户答案，另列正确答案，点击答案查看解析。缺少答案时显示“答案缺失”，不判错。
- 核对状态与作答一并保存，重开仍可查看结果；核对后点击“重做”清空当前题型全部答案并重新作答，其他题型进度和听力位置不变。
- 写作、翻译保留用户文字，核对后可查看已有参考答案自行对照。应用已移除历史、评分页面及计分逻辑。
- 阅读原文使用宽屏单栏，手机整页滚动；写作、翻译在平板分栏，手机上下排列。
- 听力音频离线播放、暂停、拖动进度和断点续听；切换题目持续播放，离开页面或切到后台暂停。

已内置 `解析结果/` 中的 **119 套真题：四级 64 套、六级 55 套**。全部通过现有 Pydantic 模型校验，保留题号、文字与选项顺序。没有外部题库导入入口。

已按用户授权为源 PDF 说明听力重复、省略的 33 套复制同场参考套的完整听力，共 825 道题，已有答案与音频同步匹配。当前仍有 3 套缺整部分阅读、1 套缺写作，共涉及 4 套试卷。缺失题型保留入口并标注“题目缺失”，用户点击后提示具体缺项，留在选题页；同套其他题型仍可正常练习。直接打开缺失题型也会提示，不生成空练习或覆盖已有进度。

## 在 HBuilderX 中运行

1. 在开发目录 `E:\CET46_practice` 执行 `npm install`、`npm run build:app`。
2. HBuilderX → 文件 → 导入 → 从本地目录导入，选择 **`E:\CET46_practice\app`**。该目录有标准 5+ `manifest.json`、`index.html`、脚本和完整离线资源，不包含开发依赖。
3. 对导入的项目选择“重新识别项目类型”，应识别为 **5+ App**；停止原 uni-app 运行，再选择“运行到手机或模拟器”。无需启动电脑上的网页服务。
4. 打包 APK 前，在 `app/manifest.json` 使用自己的 DCloud 账号生成 AppID，并配置包名、签名证书。AppID 初始为空；该配置是保留的源文件，构建不会覆盖 HBuilderX 中的 AppID、图标或平台配置，并会同步根目录的便捷启动配置。

根开发目录也有 5+ 配置，入口为 `app/index.html`，可以识别和运行；真机同步及发行建议导入上面的独立 `app/`，避免把源码、Node 依赖和其他构建目录一起同步。Vue 源码在 `src/`，修改后重新执行 `build:app`，或执行 `npm run dev:app` 自动重建；不直接编辑生成目录里的 JS/CSS。

本地浏览器预览：

```sh
npm run dev:h5
```

验证与资源编译：

```sh
npm test
npm run test:e2e
npm run build:h5
npm run build:app
npm run check:app
```

端到端测试使用本机已安装的 Chrome，分别验证 390×844 手机和 1180×820 平板布局。截图与试跑报告写入工作区 `work/`。`build:app` 生成独立 `app/` 项目，APK 仍需 HBuilderX 打包；`check:app` 检查产物，并以 `file://` 和模拟 5+ API 验证启动、原生文件、旧存储兼容、离线音频、前后台和返回键。浏览器验证不能替代 Android 真机验证。旧 `dist/build/app`、`dist/dev/app` 和 `src/hybrid/` 是历史生成物，不再作为运行入口。

## 数据和进度

- `src/data/catalog.json`：内置试卷目录。
- `src/static/papers/`：随应用打包的离线题目快照，原解析文件只读。
- `src/data/audio.json`、`src/static/audio/`：听力音频目录和离线文件。
- `scripts/package_audio.py`：开发时整理并复制套号明确的音频，Pydantic 报告写入 `work/app-audio-report.json`；运行 `E:\四六级真题\.venv\Scripts\python.exe scripts\package_audio.py`。
- `scripts/listening_reviews.py`、`scripts/web_audio_verified.json`：网络录音及同场复用关系的 Pydantic 校验；拒绝摘要变化、证据与选项不符、跨场次复用或没有明确依据的缺题试卷匹配。
- `scripts/question_supplements.py`、`scripts/question_supplements.json`：校验并应用获授权的同场听力复制，检查原 PDF、原卷及参考卷摘要；只复制听力及其已有答案，不覆盖已有原题。
- `scripts/package_library.py`：开发时打包当前工作区的内置题库，使用现有 Pydantic 模型验证整批后写入应用资源。运行 `E:\四六级真题\.venv\Scripts\python.exe scripts\package_library.py`；缺项及解析诊断单独写入 `work/app-library-report.json`，不添加到试题正文。
- `src/utils/paper.mjs`：题型到页面的适配，保留题号、文字、选项顺序；非 `available` 内容不开放作答。
- 听力分组仅影响页面展示，仍按原题号保存；填空沿用解析结果提供的字符位置定位，避免把正文中的同号数字误作空位。
- `src/utils/solutions.mjs`：按原题字母核对答案；答案与用户作答独立，不改动已有进度格式。
- `src/utils/storage.js`：逐试卷、逐题型保存，键前缀 `cet:progress:v1:`。读取失败时不覆盖旧进度，保存失败时显示重试入口。
- `src/utils/listening-player.mjs`：管理播放生命周期，位置单独保存在 `cet:audio:v1:`，按音频摘要恢复，不改动作答记录。音频替换后从头开始。

开发数据路径：解析项目、Python 环境、`解析结果/` 和临时报告 `work/` 仍位于 `E:\四六级真题`；原始题库和录音仍位于 `E:\四六级题库`。应用源码、依赖和内置资源位于 `E:\CET46_practice`，应用运行不依赖外部解析目录。

不依赖后端，不上传作答。进度保存在应用本地，卸载、清除应用数据或浏览器站点存储会清除进度。未来新增已确认无误的内置真题时，保持试卷 ID、题号和题型 ID 稳定，即可沿用已有进度。
